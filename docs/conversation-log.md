# 개인 맞춤형 AI LMS 공모전 — 타 AI 전달용 전체 인수인계 문서

> **문서 목적:** 지금까지 이 대화에서 사용자가 직접 말한 요구사항, 팀원이 작성해 전달한 기술 계획, 공모전 제출 문구 수정 방향을 빠뜨리지 않고 주제별로 통합한 자료다. 다른 AI는 이 문서를 프로젝트의 맥락으로 사용하되, **확정 사항 / 제안·검토 사항 / 서로 조율해야 할 사항**을 혼동하지 말아야 한다. 맨 끝에 이어지는 원문 발화 모음 파일도 함께 확인하면 표현과 세부 맥락을 검증할 수 있다.

## 1. 프로젝트 개요와 핵심 비전

- **주제:** 학습 자료와 생성형 AI 대화 이력을 분석해 사용자별 학습 수준을 진단하고, 요약·퀴즈·학습 경로·챗봇·대시보드를 제공하는 **개인 맞춤형 AI LMS 서비스**.
- **출발점:** 두 팀원 모두 AI로 전공을 공부하면서 ChatGPT·Claude·Gemini 등 여러 서비스에 학습 대화가 흩어지거나 대화가 초기화되어, 같은 배경지식과 설명을 반복 입력해야 했다. AI를 써서 공부했어도 **무엇을 알고, 어디가 부족한지** 객관적으로 알아보기 어려웠다.
- **기존 LMS의 한계:** 사전에 정해진 커리큘럼·이미 업로드된 학습 콘텐츠 중심으로 진행돼 학습자의 배경지식, 이해 정도, 관심과 개별 취약점에 따라 유연하게 학습 경로를 바꾸기 어렵다.
- **해결 방향:** 기존 대화/학습 기록을 재활용하고, 업로드된 자체 학습 자료 및 사이트 내 AI 상호작용을 지속 분석해 개념별 강점·약점을 보여주고, 취약 영역을 개선할 학습 방법을 추천한다.
- **주요 차별점:** 단순한 AI 요약·문제 생성기가 아니라, **여러 서비스에 흩어진 학습 경험을 연결하고 개인의 변화하는 이해도에 따라 학습 방식과 순서를 계속 바꾸는 LMS**.
- **목표:** 아이디어/문서 수준에 그치지 않고, 공모전 일정 내에 실제 작동하는 사용자 대상 서비스와 시연 결과물을 완성한다.

## 2. 두 가지 사용자 유형 — 모두 지원

**유형 A: 생성형 AI와 대화를 많이 해온 사용자**
1. ChatGPT·Claude·Gemini 등과 이전에 나눈 대화 기록을 가져와 활용한다. 구현 1단계에서 공식 대화 내보내기 파일 파싱은 **ChatGPT와 Claude** 우선, **Gemini 대화 이력 연동은 2단계** 검토.
2. 과거 대화에서 공부한 개념·배경지식·관심·이해 문제·반복 질문/재설명 필요 지점·스스로 개념을 활용한 경험을 추출한다.
3. 맞춤형 강점·약점 분석 대시보드, 커리큘럼, 문제, 학습 자료를 제시한다.

**유형 B: 생성형 AI 대화 기록이 적은 사용자**
1. 보유한 학습 자료(교재, 강의·문서, 필기, 학습 파일 등)를 업로드하고, 이 자료를 기반으로 처음부터 공부한다.
2. 자료에 맞춘 요약, 퀴즈, 커리큘럼, AI 설명을 제공한다.
3. 사이트 내 질의응답 챗봇과 퀴즈를 통해 기록이 누적되면 유형 A와 같은 방식으로 수준·강점·약점 분석을 수행한다.

**주의:** 사용자 유형은 별개의 서비스 두 개가 아니라, **같은 LMS에서 초기 데이터의 양과 형태에 따라 진입 경로가 달라지는 방식**이다.

## 3. 사용자에게 보여줄 기능 전체 목록

1. **학습 자료 업로드/관리:** 사용자가 직접 보유한 학습 자료를 제공하면 주제·핵심 개념을 추출하고 학습에 사용.
2. **생성형 AI 대화 가져오기:** 과거 ChatGPT/Claude 대화 내보내기 자료 파싱(추후 Gemini 연동).
3. **학습 자료 자동 요약:** 핵심 개념 및 내용별 요약본 생성.
4. **맞춤형 퀴즈:** 전체 자료와 약점 개념에 기반해 문제 생성; 정답률/결과를 이후 숙련도 분석에 반영.
5. **개인 맞춤 커리큘럼:** 현재 배경지식, 성취도, 약점·강점에 따라 학습할 내용과 순서를 추천·재구성.
6. **AI 요약 동영상:** 학습 자료의 내용을 정리한 AI 기반 요약 영상 제공이라는 최초 요구가 있다. 후속 보완안에서는 일정/구현 범위를 고려하여 **확장 기능(2단계 후보)**으로도 언급됐으므로 최종 우선순위 확정 필요.
7. **자료 기반 질의응답 챗봇:** 업로드한 학습 자료 내용에 근거해 질문에 답하고 모르는 개념을 설명하며, 대화 이력 또한 역량 분석의 입력값으로 이용.
8. **학습 현황 대시보드:** 얼마나 공부했는지(학습량·시간), 어느 부분을 많이 공부했는지(주제별 집중도), 개념별 숙련도, 강점과 약점을 그래프 형태로 표시.
9. **학습 보완 제안:** 왜 취약하다고 판단했는지 설명하고, 개선을 위한 퀴즈·자료·학습 순서를 추천.
10. **동적 맞춤 화면:** 정해진 레이아웃 범위 내에서 사용자 분석 결과에 맞춰 컴포넌트 배치와 학습 순서를 조정하고 **배치 이유**를 보여줌.
11. **분석 결과 갱신:** 새로운 퀴즈 응시, 챗봇 대화, 학습 활동에 맞춰 학습 프로필과 추천을 갱신.
12. **2단계 대시보드 확장:** 약점·강점 변화 추이, 판단 근거가 된 대화/학습 자료 출처까지 제공하는 기능을 추가.

## 4. 데이터 수집과 개인정보 보호 흐름

- 원칙적으로 **사용자 동의를 받고** 대화 이력·학습 자료를 수집한다.
- ChatGPT·Claude의 **공식 대화 내보내기(export) 파일**을 사용자가 제공하면 파싱한다. Gemini의 대화 이력 파싱은 후속 단계로 분류한다.
- **초기 구상:** 브라우저에서 파싱, 학습 주제 키워드 필터링, 개인정보 마스킹을 선행하고 **학습과 관련 있는 대화만** 서버로 보낸다.
- 수집 목적에 맞는 데이터 최소화, 개인정보 노출 방지, 접근권한·인증·입력값 검증, AI 생성 코드의 취약점 점검을 고려한다.
- **2단계 확장 제안:** 개인정보 마스킹 과정을 오픈소스 모델 자체 호스팅 방식으로 바꿔 외부 AI 사업자에게 원본 민감정보가 전달되지 않도록 하겠다는 팀원 초안이 있다. 다만 **브라우저 내 선처리**와 **자체 호스팅 모델의 실행 위치/데이터 전송 범위**는 아키텍처 차원에서 추가 정합성 검토가 필요하다.
- 분석의 객관성을 위해 대화만으로 사용자의 숙련도를 단정하지 않고 퀴즈 결과·직접 활용 근거와 함께 평가할 계획이다.

## 5. AI 기반 역량 분석 로직 — 세부 파이프라인

1. **개념 추출:** 학습 자료를 분석해 핵심 개념 목록을 생성한다.
2. **1차 매칭:** 개념 키워드로 ChatGPT/Claude 대화 내용 중 관련 구간을 찾는다.
3. **문맥 분류:** LLM으로 대화가 해당 개념을 **이해하지 못한 상황 / 재설명을 요청한 상황 / 스스로 활용한 상황** 등에 해당하는지 분류한다.
4. **정량 점수 계산:** LLM의 막연한 평가만으로 점수를 정하지 않는다. 개념별 대화 분류 결과와 **퀴즈 정답률**을 결합한 숙련도 점수는 **명시적 규칙을 가진 코드로 산출**한다. 구체적인 가중치·산식은 아직 확정되지 않았다.
5. **설명 생성:** LLM은 계산된 점수와 기록상의 근거를 해석해 강점·약점·취약 원인·권장 보완 방법을 자연어로 설명한다.
6. **맞춤형 경로 추천:** 숙련도 프로필에 따라 퀴즈·요약본·추천 학습 순서와 커리큘럼을 생성한다.
7. **반복 업데이트:** 새 퀴즈 및 챗봇 대화에 따라 점수를 갱신하고 대시보드에 반영한다.

### 다중 AI 분석 — 반드시 보존할 차별화 구상

- 사용자는 **이전 8인 캡스톤 프로젝트에서 사용했던 방식**을 적용하고 싶어 한다. 핵심은 **GPT, Gemini, Claude 3개 AI가 각자 독립적으로 분석·판단하고, 그 결과를 마지막 단계에서 비교·통합**하는 것이다.
- 학습자의 배경지식·관심·숙련도·강점·약점 등을 각 모델이 따로 판단하고, 공통점/차이점과 판단 근거를 종합한다.
- 판단이 다를 경우 무조건 다수결을 정답으로 삼는 것이 아니라 근거를 검토하고 필요하면 추가 퀴즈로 확인하는 방식을 이전 답변에서 제안한 바 있다. **이 검증 방안은 제안이며 확정 구현 사항은 아니다.**
- **API 선정 관련 아직 조율할 부분:** 최초 사용자 계획에는 **OpenAI API로 역량 분석**하고 GPT·Gemini·Claude의 독립 판단을 통합하겠다고 했다. 이후 팀원이 작성한 초안에는 **서비스 내 LLM API를 Claude 또는 Gemini 중 비용·성능에 따라 선정**한다고 적혔다. 따라서 **초기 MVP에서 단일 모델을 쓸지, 3모델 비교까지 구현할지, 각 제공사 API를 언제/어떻게 사용할지** 명확히 확정되지 않았다.
- 후속 수정안에서 3모델 비교를 **확장 계획**에 위치시킨 적이 있지만, 이는 기능의 가치가 낮기 때문이 아니라 비용·기간·구현 범위를 고려한 제안이다. 사용자가 강조한 원래 차별화 아이디어를 삭제하지 말아야 한다.

## 6. 사용자 맞춤 UI의 AI 활용 방식

- 모델이 화면 전체 코드를 생성하는 것이 아니라, **사전에 정한 컴포넌트와 레이아웃 시스템 안에서** 각 화면 구성의 배치와 학습 순서를 추천한다.
- LLM 출력은 **정형 JSON**으로 받고, 설계된 **스키마 검증**을 통과한 경우에만 화면에 렌더링한다.
- 사용자는 무엇 때문에 해당 순서와 구성이 추천되었는지 **배치·추천 이유**를 확인한다.
- 대시보드는 학습 기록과 숙련도를 시각화하며 2단계에는 약점 변화 및 근거 출처를 추가한다.

## 7. AI 활용 개발 방법 및 소프트웨어 품질 관리

- **바이브 코딩 / AI 페어 프로그래밍:** 사람이 서비스 요구사항과 명세·설계를 작성하고, **Claude Code**가 코드 구현을 돕는다. 개발 과정에서 ChatGPT·Claude·Gemini와 같은 생성형 AI도 보조 도구로 활용하겠다는 의견이 있었다.
- **사람이 최종 책임:** AI가 만든 코드를 팀이 직접 리뷰하고 테스트한 뒤 병합한다. 생성 결과를 그대로 무검증 배포하지 않는다.
- **CI/정적 점검:** ESLint와 GitHub Actions CI로 코드 품질·기본 검증을 자동화한다.
- **보안:** 두 사람 모두 컴퓨터보안공학 전공자로서 인증, 접근권한, 입력값 처리, 개인정보 처리 흐름, AI 생성 코드 취약점 등을 상호 교차 점검한다.
- **업무 관리:** Git/GitHub 협업 환경, GitHub Issues, 코드 리뷰, 요구사항 정의서, 기능 명세서, WBS(작업분류체계), 주간 진행 확인, 산출물 및 마일스톤 관리.

## 13. 앞으로 다른 AI가 혼동하지 않아야 할 사항

- **확정된 서비스 아이디어**와 **기술적으로 제안만 된 구현 방법**을 구분하라. 특히 AWS 세부 제품, LMS 백엔드 언어, 개념별 점수 공식, 최종 API 제공사·모델 수는 아직 확정 아님.
- 사용자 최초의 **3개 AI 독립 판단 → 비교·통합** 구상은 중요한 차별점이다. 팀원 초안의 비용·성능에 따른 Claude/Gemini API 선택과 후속안의 3모델 확장 계획을 함께 기록하고, 상충하는 부분은 최종 MVP 범위로 결정해야 한다.
- **Gemini라는 이름의 용례 2개를 구분:** ‘Gemini 대화 이력 파일을 가져오는 기능’은 2단계, ‘Gemini 모델 API를 분석에 사용하는 것’은 별개의 구현 이슈다.
- 최초 기능 요구에 **AI 요약 영상**이 포함되어 있으나 최신 AI 활용계획 수정안에서는 후속 기능으로 이동했다. 누락하지 말고 우선순위를 결정하라.
- 과거 AI 대화 내용만으로 배경지식이나 실제 실력을 단정해선 안 된다. 분류 결과, 정답률, 사용자 근거 데이터에 기반해 판단하며 사용자에게 근거를 제시하는 서비스로 설명한다.
- 데이터의 **로컬 브라우저 마스킹**과 **후속 자체 호스팅 마스킹** 간 데이터 전송 경계가 불명확하므로 보안 설계를 구체화해야 한다.
- 팀 역할(변지환/김주미)과 이전 캡스톤에서 **8인 팀장**이었다는 이력, 이번 공모전의 **팀장** 표기를 서로 혼동하지 말 것.
- 최종 문서에는 실행 역량을 객관적 경험과 계획으로 입증하고, 근거 없는 ‘정확도 향상’·‘완벽한 진단’은 보장하지 말 것.
