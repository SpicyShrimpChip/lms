# 개발 교훈 위키

개발하면서 겪은 에러·시행착오와 해결을 모아 두는 곳이다. 같은 실수를 다시 하지 않고, Claude Code가 작업 전에 읽어 참고하게 하려는 목적이다(루트 `CLAUDE.md`의 "작업 방식" 참고).

## 작성 규칙

- **다시 겪으면 시간을 잃는 것만 쓴다.** 당연한 것, 이미 `CLAUDE.md`에 규칙으로 적힌 것은 쓰지 않는다. 규칙이 있는 내용은 어디에 있는지만 가리킨다.
- **한 건은 5줄 안쪽으로 짧게.** 아래 형식을 따른다.
- 건마다 **날짜와 관련 PR 번호**를 적는다. 추정은 쓰지 않고, 확인한 것만 쓴다.
- 에러를 해결했거나 시행착오를 겪은 **같은 PR에** 한 건을 추가한다.
- **이 레포는 공개다.** 아래는 절대 쓰지 않는다.
  - 비밀번호·토큰·API 키 값, 테스트 계정 정보
  - 내 컴퓨터의 경로, 서버·DB 호스팅의 주소·계정, IP
  - 팀원·멘토의 이메일·연락처
  - 아직 고치지 않은 보안 허점(고친 뒤에 교훈으로 쓴다)
- 환경변수는 이름만 쓰고 값은 쓰지 않는다.

### 한 건의 형식

```markdown
### 제목: 증상 한 줄 (YYYY-MM-DD, #PR번호)

- 상황: 어떤 작업을 하다가 생겼는지
- 원인:
- 해결:
- 다음에는: 미리 확인할 것
```

## 목차

작업을 시작하기 전에 해당 파일의 제목을 훑는다.

### [frontend.md](frontend.md): 프론트엔드

- 직접 만든 글자 크기 토큰이 `cn()`에서 지워진다
- 화면 모드 전환을 색 섞기로 하면 글자가 잠깐 사라진다
- 굴절 유리를 넓게 걸면 스크롤이 느려진다
- `width: auto`는 전환되지 않는다
- 직접 쓴 CSS는 `components` 레이어에 둬야 Tailwind 클래스가 이긴다

### [tooling.md](tooling.md): CI·Git·배포

- 패키지가 늘어난 뒤에는 다른 컴퓨터에서 `npm ci`를 다시 한다
- Prettier 검사는 CI가, 고치는 건 커밋 훅이 한다
- 도커: `docker --version`은 되는데 연결 오류가 난다
- VS Code PostgreSQL 확장 접속 오류 세 가지
- 백엔드 CI를 필수 검사로 켜는 순서
- npm 12가 공식 registry 파일까지 막는다(Renovate 임시 제한)
- Claude는 강제 푸시가 막혀 있다
- GitHub Actions 대기열이 길 때
- Vercel 환경변수가 빠지면 화면이 `/api`를 실제로 부른다

### [process.md](process.md): 문서·진행 방식

- 개인정보 처리방침은 작성지침 원문 항목에 맞춘다

### [backend.md](backend.md): 백엔드 (초안, 주미 님 확인 필요)

- 머지된 마이그레이션은 고치지 않고 새 버전을 추가한다
- 앱 DB 계정과 마이그레이션 계정을 나눈다
- 역할은 토큰이 아니라 요청마다 DB에서 읽는다
- 공지 본문은 HTML로 해석하지 않고 글자 그대로 저장한다
- MySQL에서 PostgreSQL로 옮길 때 H2 테스트를 지키는 법
